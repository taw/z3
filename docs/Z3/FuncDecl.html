      class Z3::FuncDecl

      Constants

      PARAMETER_KINDS

      Decl parameters are the ‘_`-part of an indexed decl like `(_ map or)`, `(_ extract 7 0)`, `(_ zero_extend 8)`. They have nothing to do with the domain, so they’re not counted by arity.

def ==(other)
  eql?(other)
end

      Z3 hash-conses declarations, so two decls of the same name and signature are one and the same. AST already gives us eql? and hash on the pointer; without this they’d disagree with ==, which would be an odd thing for a Hash key to do. (Expr overrides == to build an expression instead - a FuncDecl is not a value, so there’s nothing to build.)

def [](*args)
  unless args.size == arity
    raise Z3::Exception, "#{name} takes #{arity} argument#{"s" unless arity == 1}, got #{args.size}"
  end
  range.new(LowLevel.mk_app(self, args.each_with_index.map { |arg, i| domain(i).cast(arg) }))
end

      Applies the function. Arguments are cast to the declared domain and the result has the declared range, so it composes like any other expression.

      # File lib/z3/func_decl.rb, line 58
def parameter(i)
  case (kind = parameter_kind(i))
  when :int
    LowLevel.get_decl_int_parameter(self, i)
  when :double
    LowLevel.get_decl_double_parameter(self, i)
  when :rational
    # Z3 hands this one over as a string, in Ruby's own `3/4` spelling
    Rational(LowLevel.get_decl_rational_parameter(self, i))
  when :symbol
    LowLevel.symbol_value(LowLevel.get_decl_symbol_parameter(self, i))
  when :sort
    Sort.from_pointer(LowLevel.get_decl_sort_parameter(self, i))
  when :ast
    Expr.new_from_pointer(LowLevel.get_decl_ast_parameter(self, i))
  when :func_decl
    func_decl_parameter(i)
  when :zstring
    raise Z3::Exception, "Parameter #{i} is a string, and Z3 offers no way to read one back - use Expr#value on the literal instead"
  else
    raise Z3::Exception, "Parameter #{i} is #{kind}, which Z3 keeps to itself"
  end
end

      What the decl is indexed by, as an ordinary Ruby object. The decl name is the same for every extract - ‘(_ extract 7 0)` and `(_ extract 3 2)` are both called “extract” - so the parameters are the only place the 7 and the 0 exist.

      Two of the nine kinds can’t be read back: ‘:zstring` has no accessor in the C API at all (use `Expr#value` on the literal instead), and `:internal` is opaque by definition.

def parameter_kind(i)
  raise Z3::Exception, "Trying to access parameter #{i} but decl has #{num_parameters} parameters" if i < 0 or i >= num_parameters
  k = LowLevel.get_decl_parameter_kind(self, i)
  PARAMETER_KINDS.fetch(k) { raise Z3::Exception, "Unknown decl parameter kind #{k}" }
end
